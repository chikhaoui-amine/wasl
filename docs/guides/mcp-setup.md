# Model Context Protocol (MCP) Setup Guide

WASL Local includes a local **Model Context Protocol (MCP)** connector so compatible AI clients can work with the parts of your WASL workspace you explicitly allow.

The connector runs on your computer and communicates with the active WASL browser/PWA instance over authenticated loopback (`127.0.0.1`).

## Before you start

From the repository root:

```bash
npm install
npm run build:mcp
npm run dev
```

Then open **http://localhost:3000** and keep that WASL instance running while you use the connector.

## Create an AI connection

1. Open **Settings → AI connections** in WASL.
2. Enable the local MCP connector if it is disabled.
3. Create a connection for your AI client.
4. Choose **Read only** or **Read + write** access.
5. Select the WASL domains that connection is allowed to access.
6. Copy the configuration generated by WASL for that connection.

Each connection has its own local secret and can be disabled, revoked, rotated, renamed, or deleted independently.

## Client examples

WASL can generate copy-ready configuration for supported presets in **Settings → AI connections**. Prefer the generated configuration because it includes the correct local port, connector secret, and current path.

### Claude Code

A typical STDIO connection is equivalent to:

```bash
claude mcp add wasl node <PATH_TO_WASL_REPO>/packages/wasl-mcp-local/dist/cli.js --secret=YOUR_CONNECTOR_SECRET
```

Use the exact command generated by WASL when available.

### Claude Desktop

A typical `claude_desktop_config.json` entry looks like:

```json
{
  "mcpServers": {
    "wasl": {
      "command": "node",
      "args": [
        "<PATH_TO_WASL_REPO>/packages/wasl-mcp-local/dist/cli.js",
        "--secret=YOUR_CONNECTOR_SECRET"
      ]
    }
  }
}
```

### Codex

Add WASL as a local STDIO MCP server using the command/configuration shown in **Settings → AI connections**. The important values are the built connector entry point and the secret for the selected connection profile.

### Cursor

Add a new local MCP server and use the generated STDIO command from WASL. If configuring it manually, the command targets:

```text
node <PATH_TO_WASL_REPO>/packages/wasl-mcp-local/dist/cli.js --secret=YOUR_CONNECTOR_SECRET
```

## Security model

- Communication is local loopback only.
- Connector profiles have independent secrets.
- Access can be read-only or read-write.
- Allowed domains are configurable per connection.
- Sensitive domains can be gated separately.
- WASL keeps a local MCP audit log.

See [Local MCP architecture](../architecture/local-live-mcp.md) and the [security model](../security/security-model.md) for implementation details.

## Important limitation

WASL Local stores its data in the browser's IndexedDB. The WASL browser/PWA instance and your computer must therefore be running for the local MCP connector to access that data.

If the computer is off, WASL Local cannot receive scheduled or remote MCP requests.
